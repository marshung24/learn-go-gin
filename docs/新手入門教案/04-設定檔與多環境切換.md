## 核心觀念

### Viper 設定管理

```go
import "github.com/spf13/viper"

func LoadConfig() {
    viper.SetConfigFile(".env")
    viper.AutomaticEnv()  // 環境變數自動綁定

    if err := viper.ReadInConfig(); err != nil {
        log.Println("No .env file found, using environment variables")
    }
}

// 使用設定值
dbHost := viper.GetString("DB_HOST")
dbPort := viper.GetInt("DB_PORT")
```

Viper 支援 .env 檔、環境變數、YAML 等多種來源，自動綁定 struct。

### 環境變數優先於檔案

```bash
# .env 檔案中
DB_HOST=localhost

# 但執行時設定環境變數
DB_HOST=db go run main.go  # 會用 db 而非 localhost
```

容器環境可用環境變數覆寫設定，不需改檔案。

### `.env` 檔案

開發環境常用的設定方式，不應 commit 到 git（用 `.env.example` 作範本）：

```env
# .env.example
APP_PORT=8080
DB_HOST=localhost
DB_PORT=3306
DB_USER=app
DB_PASSWORD=app
DB_NAME=app
REDIS_HOST=localhost
REDIS_PORT=6379
```

### Docker Compose 一鍵啟動

```yaml
# docker-compose.yml
services:
  app:
    build: ./docker/go
    ports:
      - "8080:8080"
    depends_on:
      - db
      - redis

  db:
    image: mysql:8.0
    environment:
      MYSQL_DATABASE: app
      MYSQL_USER: app
      MYSQL_PASSWORD: app

  redis:
    image: redis:7-alpine
```

一個 `docker compose up -d` 拉起 App + MySQL + Redis 三個容器。

### 本機 vs 容器的設定差異

| 設定 | 本機 | 容器 |
|------|------|------|
| DB_HOST | localhost | db |
| REDIS_HOST | localhost | redis |

容器內服務間用 service name 互連，不是 localhost。

## 動手做

### 必做

**1. 啟動完整環境**

```bash
docker compose up -d
docker compose ps
```

確認三個容器（app / db / redis）都在 running 狀態。

**2. 比對設定差異**

比對 `.env.example` 中本機與容器環境的設定差異，說明為什麼容器內 DB host 是 `db` 而非 `localhost`。

## 踩坑提示

| 現象 | 原因 | 解法 |
|------|------|------|
| `docker compose up` 後 App 啟動失敗 | MySQL 容器尚未 ready | 等 healthcheck 通過後重試，或查看 `docker compose logs app` 確認錯誤 |
| `.env` 變數沒生效 | 忘了從 `.env.example` 複製為 `.env` | `cp .env.example .env` 後重新啟動 |
| Viper 讀不到環境變數 | 沒有呼叫 `viper.AutomaticEnv()` | 確認 config 初始化時有啟用環境變數自動綁定 |
