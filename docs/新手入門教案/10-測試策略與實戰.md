## 為什麼先教這個？

不寫測試的程式碼是「可能會動」，有測試的程式碼是「確定會動」。測試是修改程式碼後不會造成回歸錯誤的安全網——這是從「學習專案」走向「生產專案」的關鍵一步。

## 核心觀念

### 測試金字塔

```
        /\
       /  \     E2E 測試（少且慢）
      /----\
     /      \   整合測試
    /--------\
   /          \  單元測試（多且快）
  --------------
```

先追求單元測試覆蓋，再補整合測試。

### Go testing 基礎

```go
// 測試函式命名規則：Test + 函式名
func TestGetByID_Success(t *testing.T) {
    // Arrange（準備）
    // ...

    // Act（執行）
    result, err := service.GetByID(1)

    // Assert（驗證）
    if err != nil {
        t.Errorf("expected no error, got %v", err)
    }
    if result.Title != "Clean Code" {
        t.Errorf("expected 'Clean Code', got %s", result.Title)
    }
}

// 子測試
func TestGetByID(t *testing.T) {
    t.Run("Success", func(t *testing.T) {
        // ...
    })

    t.Run("NotFound", func(t *testing.T) {
        // ...
    })
}
```

### mockery 產生 mock

根據 interface 自動產生 mock struct：

```bash
# 安裝 mockery
go install github.com/vektra/mockery/v2@latest

# 產生 mock（會讀取 interface 定義）
mockery --name=BookRepository --output=mocks
```

使用 mock：

```go
func TestGetByID_Success(t *testing.T) {
    // 建立 mock
    mockRepo := new(mocks.BookRepository)

    // 設定預期行為
    mockRepo.On("FindByID", uint(1)).Return(&Book{
        ID:    1,
        Title: "Clean Code",
    }, nil)

    // 注入 mock
    service := NewBookService(mockRepo, nil)

    // 執行
    result, err := service.GetByID(1)

    // 驗證
    assert.NoError(t, err)
    assert.Equal(t, "Clean Code", result.Title)

    // 確認 mock 方法被呼叫
    mockRepo.AssertExpectations(t)
}
```

### httptest — 測試 Handler

建立假的 HTTP 請求測試 handler，不需要真的啟動 server：

```go
func TestGetBooks_Success(t *testing.T) {
    // 建立 mock service
    mockService := new(mocks.BookService)
    mockService.On("GetAll").Return([]BookResponseDTO{
        {ID: 1, Title: "Clean Code"},
    }, nil)

    // 建立 handler
    handler := NewBookAPIHandler(mockService)

    // 建立假 request
    req := httptest.NewRequest("GET", "/api/books", nil)
    rec := httptest.NewRecorder()

    // 建立 Gin context
    c, _ := gin.CreateTestContext(rec)
    c.Request = req

    // 執行
    handler.GetBooks(c)

    // 驗證
    assert.Equal(t, http.StatusOK, rec.Code)

    var books []BookResponseDTO
    json.Unmarshal(rec.Body.Bytes(), &books)
    assert.Len(t, books, 1)
    assert.Equal(t, "Clean Code", books[0].Title)
}
```

### Table-driven tests

Go 社群慣用的測試風格：

```go
func TestGetByID(t *testing.T) {
    tests := []struct {
        name      string
        id        uint
        mockSetup func(*mocks.BookRepository)
        wantErr   bool
        wantTitle string
    }{
        {
            name: "Success",
            id:   1,
            mockSetup: func(m *mocks.BookRepository) {
                m.On("FindByID", uint(1)).Return(&Book{Title: "Clean Code"}, nil)
            },
            wantErr:   false,
            wantTitle: "Clean Code",
        },
        {
            name: "NotFound",
            id:   99,
            mockSetup: func(m *mocks.BookRepository) {
                m.On("FindByID", uint(99)).Return(nil, gorm.ErrRecordNotFound)
            },
            wantErr: true,
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            mockRepo := new(mocks.BookRepository)
            tt.mockSetup(mockRepo)

            service := NewBookService(mockRepo, nil)
            result, err := service.GetByID(tt.id)

            if tt.wantErr {
                assert.Error(t, err)
            } else {
                assert.NoError(t, err)
                assert.Equal(t, tt.wantTitle, result.Title)
            }

            mockRepo.AssertExpectations(t)
        })
    }
}
```

func TestFindByID_NotFound(t *testing.T) {

## 踩坑提示

| 現象 | 原因 | 解法 |
|------|------|------|
| mock 方法沒被呼叫，測試仍通過 | 沒有用 `AssertExpectations` 驗證 | 在測試結尾加 `mockRepo.AssertExpectations(t)` |
| httptest 回傳空 body | ResponseRecorder 沒有正確讀取 | 用 `rec.Body.String()` 或 `rec.Body.Bytes()` 取得回應 |
| 測試間互相影響 | 共用了全域狀態 | 每個測試函式重新建立 mock 和待測物件 |
